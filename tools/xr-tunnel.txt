XR / HTTPS tunnel — DIY boot guide (Quest + local Sculpt)

WebXR on Meta Quest needs HTTPS. A tunnel (Cloudflare, ngrok, etc.) exposes your
local `npm run server` so the headset can load the app.

This file is for anyone reproducing a similar setup. It does not include account
secrets — you create your own tunnel and hostname.

==============================================================================
WHAT YOU NEED
==============================================================================
- This repo built and serving `app/` on a local port (default 8080)
- A tunnel client (e.g. cloudflared) pointed at that port
- An HTTPS hostname that reaches the tunnel (Cloudflare Tunnel, ngrok URL, …)
- Meta Quest Browser on the same network path as that hostname

==============================================================================
1) BUILD + SERVE LOCALLY
==============================================================================
In the repo:

  npm install
  npm run release
  npm run server

Confirm on the PC:

  http://127.0.0.1:8080/

`tools/xr-dev-server.js` serves `app/` with no-cache and relays Quest logs to
`/__xr_logs` (and accepts POSTs at `/__xr_log`).

Alternate scripts:

  npm run boot:test     # release + server
  npm run serve:tunnel  # same server on port 5173 (if your tunnel targets 5173)

==============================================================================
2) POINT A TUNNEL AT LOCALHOST
==============================================================================
Example with Cloudflare Tunnel (any similar HTTPS tunnel works):

  Published application / public hostname
    → Service: http://localhost:8080
       (or http://127.0.0.1:8080 / http://host.docker.internal:8080 as needed)

Keep the tunnel client HEALTHY while testing.

WSL note: if cloudflared runs in WSL but Node runs on Windows, do not use WSL
`localhost` for the Windows server — use the Windows host IP, or bind the
server to 0.0.0.0 and route accordingly.

You do not need CIDR routes for a simple public hostname; a published app
route to localhost is enough for Quest testing.

==============================================================================
3) OPEN ON QUEST
==============================================================================
In Meta Quest Browser, open YOUR https hostname, e.g.:

  https://YOUR-TUNNEL-HOST.example/

Hard-refresh after rebuilding so `sculptgl.js` updates.

On a headset browser, WebXR Sculpt setup should auto-open when immersive XR is
supported. Use “Use desktop instead” to stay in 2D; the corner “XR setup…” chip
remains available.

==============================================================================
4) LIVE LOGS (laptop)
==============================================================================
While the Quest page is open:

  http://127.0.0.1:8080/__xr_logs

Or the same path through your tunnel:

  https://YOUR-TUNNEL-HOST.example/__xr_logs

Filter for [XRSetup], XRControllerModels, Import URL, MR VIEW.

If the HTML toolbar is missing in-headset MR, hold BOTH grip (squeeze) buttons
~2.5 seconds to exit.

==============================================================================
5) IMPORT VIA URL (SAME ORIGIN)
==============================================================================
Place meshes under `app/` (served at `/`). Sample after release:

  app/models/Duck.glb

On Quest (relative URL — same origin, no CORS hassle):

  https://YOUR-TUNNEL-HOST.example/?modelurl=/models/Duck.glb

Desktop Files → Import URL also works for HTTPS hosts that send CORS
(`Access-Control-Allow-Origin`). Do not use `http://localhost/...` on Quest —
the headset cannot see your PC’s localhost.

==============================================================================
6) OPTIONAL — PORT 5173
==============================================================================
If your tunnel service is `http://localhost:5173`:

  npm run xr-dev

and keep Cloudflare (or other) Service matching that port.

==============================================================================
EXAMPLE (Messiah Studios — replace with yours)
==============================================================================
One working pattern used while developing this fork:

  Tunnel hostname:  https://xr-dev.messiahstudios.site
  Local service:    http://localhost:8080
  Quest opens:      https://xr-dev.messiahstudios.site
  Logs:             http://localhost:8080/__xr_logs

Treat that as an illustration only. Publish your own hostname for your own
tunnel; do not assume that example URL is always online.

==============================================================================
SECURITY NOTES
==============================================================================
- Tunnel docs should never store API tokens, certs, or Zero Trust secrets.
- A public hostname only serves traffic while YOUR tunnel + `npm run server`
  are running.
- Prefer temporary / Zero Trust access policies if you do not want the app
  open to the whole internet during testing.
